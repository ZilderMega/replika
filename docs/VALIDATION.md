# Проверка audio-engine — 7 ноября 2026

## Среда и результат

Windows, JDK 21, Android SDK 35, NDK 27.1.12297006, CMake 3.22.1. Android Emulator `Medium_Phone_API_36.1`, x86_64, 6 виртуальных CPU, 2 ГБ RAM. Это эмулятор на компьютере, не измерение скорости физического телефона. APK содержит ARM64 и x86_64; на ARM64 выполнена сборка, запуск на физическом устройстве пока не проверен.

- `assembleDebug`: успешно.
- `testDebugUnitTest`: 6 тестов, успешно.
- `lintDebug`: 0 ошибок; предупреждения о версиях зависимостей/target SDK, иконке и KTX.
- Instrumentation: **7 тестов, 0 ошибок**, 36,026 с на последнем полном прогоне. Лог: `artifacts/instrumentation.txt`.
- В объединённом манифесте приложения отсутствует INTERNET. Инференс выполнялся в процессе Android-приложения, без серверной обработки.

## Что проверялось на Android

1. Русский `0.wav`: полный конвейер, обе версии текста, запуск локальной LLM, границы времени. Итог ASR: «я тебя люблю». Короткое «я» сохранено с `speaker_unknown`, поскольку диаризатор не определил для него участника.
2. Официальный `1-two-speakers-en.wav`: автоматическая кластеризация дала ровно 2 участника без задания их количества. Нативные ID 0 и 3; приложение перенумеровывает их по первому появлению.
3. Русский `1.wav`: полный конвейер; распознан текст «родион потапыч высчитывал каждый новый вершок углубления и давно определил про себя». LLM сохранила слова. Созданный из тестовой записи MP3 44,1 кГц stereo успешно декодирован в mono 16 кГц с ожидаемой длительностью.
4. Повреждённый комплект моделей отклоняется до нативной загрузки.
5. Двухсекундная цифровая тишина даёт пустую расшифровку; повреждённое аудио — ошибку.
6. Прямой ASR полного WAV используется для проверки того, что предварительное разбиение не потеряло слово.
7. Отмена на этапе ASR завершает coroutine и удаляет временный PCM.

Модульные тесты проверяют стабильную нумерацию участников, неопределённость при перекрытии, запрет LLM менять слова/числа/порядок, сборку субслов, исходную шкалу времени, длительность ресемплинга и пустой результат.

## Измерения последнего полного прогона

`0.wav`, 9,240 с: полный конвейер 8,788 с (RTF 0,95). Проверка моделей 1,194 с; декодирование 0,289 с; диаризация 1,140 с; ASR 2,443 с; сборка 0,007 с; LLM 3,714 с.

`1.wav`, 7,080 с: полный конвейер 10,881 с (RTF 1,54). Проверка моделей 0,677 с; декодирование 0,111 с; диаризация 0,971 с; ASR 2,307 с; сборка 0,001 с; LLM 6,814 с.

Снимок `/proc/<pid>/status` после второго примера: VmHWM 741368 kB (около 724 МиБ пикового resident set за жизнь тестового процесса), текущий VmRSS 217060 kB, VmSwap 63736 kB. Это не peak PSS, не полный расход памяти системы и не гарантия для длинных файлов. Эмулятор использовал swap. Однократные скорости зависят от кэшей, нагрузки и состояния эмулятора; на раннем прогоне LLM занимала десятки секунд. Нативное ядро теперь компилируется с `-O3` и в debug APK.

## Найденные и исправленные проблемы

- JNI callback sherpa несовместим с Kotlin indy-лямбдами: переключён `-Xlambdas=class`, реальный повторный запуск прошёл.
- Жёсткое использование диаризации как VAD удаляло короткий токен. ASR теперь обрабатывает всю запись окнами с контекстом, кроме цифровой тишины.
- ASR выдавал токен на полностью нулевом сигнале: добавлена проверка цифровой тишины.
- Конец слова растягивался через длинную паузу до следующего токена: теперь ограничен временем последнего токена + 300 мс.
- Эмулятор заполнился дублирующей копией моделей; тестовый скрипт удаляет staging-файлы после копирования и проверяет ошибки установки/результат instrumentation, а не только код выхода adb.

## Что ещё не доказано

Нет измерений WER/DER или точности временных границ по независимо размеченному корпусу. Два найденных участника не доказывают корректное распределение каждого слова. Нет теста реального русского многоголосого совещания, наложившихся голосов, 30-минутной записи и физического телефона с 4 ГБ RAM. LLM 0.5B не гарантирует хорошую пунктуацию: например, на короткой фразе она предложила «Тебя Люблю». Исходный экспорт остаётся неизменным.

Foreground service, история, восстановление задания после убийства процесса и встроенный плеер не входят в эту реализацию движка. Последний результат записывается в приватный JSON, но история/повторное открытие из UI ещё не реализованы.

## Обновление 0.3 — модели внутри APK

Модели ASR, диаризации и Qwen включены в `assets/models` основного APK. Проверено наличие всех восьми файлов внутри собранного APK. Размер сборки — около 634 МБ; отдельный ZIP пользователю не нужен.

На отдельном чистом хранилище Android Emulator (API 36.1, x86_64, 2 ГБ RAM) установлен только APK. До первого запуска приватной папки моделей не было. После запуска приложение самостоятельно создало и проверило модели и показало «Готово к работе». В интерфейсе отсутствует импорт моделей. Исходное хранилище эмулятора не стиралось.

Тестовый скрипт больше не копирует модели через adb: все Android-тесты получают их из APK. Дополнительно проверяются отсутствие повторного копирования при следующем запуске и восстановление повреждённого tokens.txt из встроенной копии. Для установки и обновления большого APK требуется свободное место: установка на старом переполненном эмуляторе с 1,4 ГБ свободного пространства не прошла; на чистом хранилище с 4,8 ГБ прошла.

Итог проверки 0.3: **9 Android-тестов прошли, 0 ошибок**, включая распознавание с LLM, автоматическое восстановление повреждённого файла из APK и отсутствие повторного копирования готовых моделей. Длительность полного прогона на новом хранилище эмулятора — 243,303 с; это функциональная проверка, не сопоставимый бенчмарк с предыдущим прогретым эмулятором. Сборка и 6 модульных тестов прошли, Lint — без ошибок. Лог нового прогона: `artifacts/bundled-instrumentation.txt`.

## Обновление 0.4 — запись и длинное аудио

Добавлен RecordingService с типом microphone, разрешениями RECORD_AUDIO и foreground service. Запись запускается после выдачи разрешения пользователем, сохраняется в приватную папку recordings в M4A/AAC. Есть уведомление с остановкой и продолжение записи при заблокированном экране. В приложении показываются последние пять записей; после остановки результат выбран для расшифровки. Прослушивание приватных записей использует FileProvider. Это запись с последующей расшифровкой, без потокового показа текста во время разговора.

Убраны обе проверки длительности в декодере. Диаризация читает максимум пять минут PCM за вызов; голоса соседних блоков сопоставляются по нормированным CAMPPlus-эмбеддингам с порогом cosine 0.65. Участник с недостаточной длиной аудио остаётся неизвестным. Глобальное сопоставление на реальных длинных интервью ещё требует оценки и настройки; возможны ошибочные объединения/разделения участников. Лимит импорта 1 ГБ и ограничения свободного места сохраняются.

Для ASR короткий вход дополняется до секунды. При исключении распознавание повторяется на половинах окна до участка в две секунды; если оно по-прежнему невозможно, ошибка содержит исходный интервал и сообщение библиотеки. Это обработка отказа, а не доказанное исправление всех причин ONNX Reshape. Пользовательский исходный MP3 недоступен; песни по просьбе пользователя не исследовались.

На тестовом речевом MP3 длиной 35 секунд воспроизведена ошибка Reshape_3 в /encoder/encoders.0/layers.0/self_attn_weights, аналогичная сообщению пользователя. Повторное распознавание уменьшенными окнами завершилось успешно. Основное окно затем уменьшено с 20 до 6 секунд (до 8 секунд с контекстом), чтобы не подавать в encoder проблемный длинный вход; адаптивное повторение сохранено. Нельзя утверждать, что проверен исходный пользовательский файл.

Проверки: первый прогон 10 Android-тестов прошёл, включая 31-минутный WAV цифровой тишины. Отдельно прошли запись реального M4A через MediaRecorder с последующим декодированием и распознавание речевого MP3 через несколько окон (2 теста). Цифровая тишина проверяет длительность и ресурсный путь, но не качество длинного интервью. Для окончательного изменения размера окна выполнен дополнительный регрессионный прогон короткого WAV и длинного MP3.

Окончательный прогон после уменьшения окна: оба регрессионных теста прошли за 47,204 с. В логах этого процесса ошибка Reshape отсутствует. APK: artifacts/replika-0.4-bundled-debug.apk. Логи: artifacts/window-tests.txt, artifacts/recording-tests.txt, artifacts/long-audio-tests.txt. Модульные тесты и Lint прошли; проверка физического телефона и качества сопоставления участников на многочасовых интервью остаётся необходимой.
