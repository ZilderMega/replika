# Реплика

Android-приложение для локальной расшифровки русского аудио. Ветка `feat/audio-engine`, версия 0.4. Android 8+; ARM64 и x86_64.

## Что реализовано

- Запись с микрофона в M4A/AAC, в том числе при заблокированном экране, с уведомлением и кнопкой остановки. После сохранения запись доступна для расшифровки.
- Импорт аудио через системный выбор файла; декодирование Android MediaExtractor/MediaCodec, сведение каналов и PCM 16 кГц во временный файл.
- Локальные Pyannote segmentation + CAMPPlus embeddings: поиск речи и автоматическая кластеризация участников в пределах записи.
- Русский small Zipformer: распознавание речевых окон с временными метками токенов, сборка слов и реплик.
- Qwen2.5 0.5B Q4_K_M через JNI llama.cpp: отдельный вариант пунктуации. Изменение слов, чисел или их порядка отклоняется.
- Все модели, включая локальную LLM, встроены в APK. Первый запуск автоматически подготавливает и проверяет их; отдельные загрузки и импорт не нужны. Есть прогресс, отмена, просмотр, переключение исходного/обработанного текста и экспорт исходного JSON.
- Последний результат сохраняется в приватном `files/last-result.json`; история и восстановление экрана после перезапуска пока не реализованы.

Ни распознавание, ни LLM не используют сервер. В APK нет разрешения INTERNET. Большие модели и сторонние библиотеки не коммитятся в Git.

## Подготовка и сборка (Windows, PowerShell 7)

Установить JDK 17+, Android SDK 35, NDK 27.1.12297006, CMake 3.22.1, Git и curl. Путь Android SDK указать в исключённом из Git `local.properties`.

```powershell
./scripts/setup-engine.ps1
./gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

Скрипт разработчика скачивает зафиксированные зависимости и модели на компьютер с проверкой SHA-256. Gradle автоматически включает восемь необходимых файлов из `.models` в APK; при отсутствии файлов сборка завершается ошибкой. Модели не коммитятся в Git. Результат Gradle: `app/build/outputs/apk/debug/app-debug.apk`.

**Пользователю нужен только APK:** `artifacts/replika-0.4-bundled-debug.apk` (около 634 МБ). Установить, открыть приложение, дождаться автоматической подготовки и выбрать аудио. ZIP, регистрация, интернет и компьютер при обработке не нужны.

Нативным библиотекам нужны обычные файлы, поэтому при первом запуске модели копируются из APK в приватную папку приложения и проверяются. Подготовка выполняется вне UI-потока; после прерывания её можно повторить. При следующих запусках подходящие модели повторно не копируются. Повреждённые файлы восстанавливаются из APK. При обновлении комплекта используется временная папка и замена после проверки.

На устройстве APK и подготовленные модели вместе занимают примерно 1,2 ГБ плюс системные накладные расходы. Для установки и обновления лучше иметь не менее 3 ГБ свободного места.

## Проверка

```powershell
# Подключённый эмулятор/телефон; идентификатор из adb devices
./scripts/test-device.ps1 -Serial emulator-5554
```

Для инструментальных проверок нужен ffmpeg в PATH (подготовка stereo MP3). Тестовый русский WAV берётся из официального архива ASR. Отдельный английский диалог с двумя участниками проверяет диаризацию; он не используется для оценки русского ASR. Скрипт устанавливает debug APK и тестовый APK, подготавливает модели исключительно из APK и запускает реальный инференс на Android и выгружает `artifacts/smoke-result.json`. Через `run-as` копируются только тестовые аудиофайлы; для обычного пользователя это не требуется.

Подробности реализации, ограничения и источники: [docs/AUDIO_ENGINE.md](docs/AUDIO_ENGINE.md). Результаты проверок: [docs/VALIDATION.md](docs/VALIDATION.md).

## Ограничения первой версии

Предел в 30 минут снят; импорт файлов пока ограничен 1 ГБ. Диаризация выполняется блоками по 5 минут, ASR — окнами по 6 секунд с контекстом. Во время обработки приложение следует держать открытым; foreground service и восстановление задания после убийства процесса относятся к следующему этапу. Поворот экрана не перезапускает инференс. Отмена проверяется между нативными вызовами; диаризация может завершать текущий вызов до освобождения ресурсов.

Временные границы приблизительные, получены из ASR-токенов и диаризации, а не из forced alignment. Одновременная речь не разделяется на независимые аудиопотоки; неоднозначный участник обозначается `speaker_unknown`. Хорошее качество на произвольных русских встречах ещё нужно измерить на размеченном корпусе и физических телефонах.
